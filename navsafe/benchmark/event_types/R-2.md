# R-2 · Bicycle-Involved — review checklist

Cyclists where cyclists legitimately are, riding ahead of and beside the ego,
so the ego repeatedly has to judge whether there is room to pass.

| | |
|---|---|
| **built by** | `R-2.yaml` — the **whole** `bicycle_rider` bank, `count: all`. Event type variety is a property of the bank, not of who typed the spec. |
| **placement** | `bike_lane_chain`: the host's mapped bike lane where it has one (nuPlan maps do carry them), else its rightmost same-direction lane — which is where a cyclist rides on a street without one. `arc: auto`, 8 m apart over 30 m. Laterals are **+left**, so the `−0.8…−1.2 m` here is toward the kerb. |
| **behaviour** | `dynamic` -> `idm` at 3.2–4.5 m/s. Slower than the ego, so the overtake happens by itself rather than having to be provoked. |

## What a human confirms

- [ ] the cyclists are in a lane a cyclist would actually use — check whether the host gave a **dedicated** bike lane or the **rightmost general** one; they are different scenarios
- [ ] they are strung out, not abreast: a bunch riding shoulder to shoulder is one obstacle
- [ ] passing room is genuinely marginal — if the ego can pass without deviating, the event type tests nothing
- [ ] contact would read as VRU severity, not vehicle severity

> **Previously.** This event type declared five cyclists in five different
> relationships to the ego (crossing, oncoming, kerbside, in-lane, and a second
> crossing). That is five event types wearing one label, and the crossing cases
> duplicated R-3's template.

## Applies to every event type

- [ ] the asset renders at all, at the right scale, upright, and sitting on the road
- [ ] an actor the manager is not driving this frame is parked far off-screen,
      not deleted — confirm that parked pose is not visible from another camera
- [ ] the actor is close enough, and early enough, that the policy under test
      actually meets it — a recipe pins a spawn, not a meeting, so only the
      rendered episode can show this
